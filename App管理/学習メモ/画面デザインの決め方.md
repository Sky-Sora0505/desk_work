# アプリの画面デザインの決め方

手書きから実装までの流れと、日本の業務での道具です。

## 19-2. アプリの画面デザインの決め方

手書きはふつうに使います。流れは次のとおりで、個人開発なら 2 から 5 に飛ぶことも多いです。

1. 何をするアプリかを言葉で決める（誰が、何のために、いちばんよく使う操作は何か）
2. ワイヤーフレーム：色や飾りなしで、四角と線だけで「どこに何を置くか」を描く。手書きが速い
3. モックアップ：色・文字・余白まで決めた完成図
4. プロトタイプ：ボタンを押すと画面が切り替わる「触れる見本」
5. 実装

| 道具 | 特徴 |
| --- | --- |
| 紙とペン | 最速。方眼ノートが便利 |
| Figma | Web 系の事実上の標準。ブラウザで動き、無料プランがある |
| Excalidraw | 手書き風の図がすぐ描ける。ワイヤーフレーム向き |
| Penpot | Figma に似たオープンソース。Docker で自分のサーバーにも置ける |
| Sketch | Mac 専用の老舗 |

| 日本の業務での使われ方 | 道具 | 理由 |
| --- | --- | --- |
| SIer・受託開発 | Excel（Excel 方眼紙で画面設計書・画面遷移図）、PowerPoint | お客さんも社内も全員が開け、設計書として印刷・承認・保管しやすい |
| Web 系・自社サービス・スタートアップ | Figma | デザイナーとエンジニアが同じファイルを見て、余白や色の数値を拾える |
| よく併用されるもの | draw.io（画面遷移図・構成図）、Cacoo（国産の作図ツール）、Miro（オンラインのホワイトボード） | — |

実務で効くのは道具の操作より、**画面一覧・画面遷移図・項目定義（入力欄の桁数や必須かどうか）を書く力**です。センスを補うには、Apple の Human Interface Guidelines や Google の Material Design といった「お手本」に乗るのが近道です。倉庫のアプリなら、紙に iPhone の縦長の枠を描いてワイヤーフレームを手書きし、その写真から HTML を起こすのがいちばん速いです。
