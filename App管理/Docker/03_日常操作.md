# 日常の操作（起動・停止・確認）

毎日の操作と、起動・停止スクリプトの解説です。スクリプトの実物は `scripts/` にあります。

日常の操作は `status.sh`（確認）、`up.sh`（起動）、`down.sh`（停止）の3つでほぼ足ります。「サーバーを止める」と「電源を切る」は別の操作です。

## 8-1. スクリプト全文

`~/server/scripts/up.sh`（実行権限あり）

```bash
#!/bin/bash
set -u
TS_IP="100.x.y.z"
SERVICES=(apps homepage)

for i in $(seq 1 30); do
  if tailscale ip -4 2>/dev/null | grep -q "^${TS_IP}$"; then break; fi
  echo "Tailscale の接続を待っています... (${i}/30)"
  sleep 2
done

if ! tailscale ip -4 2>/dev/null | grep -q "^${TS_IP}$"; then
  echo "エラー: Tailscale が接続されていません。起動を中止します。"
  exit 1
fi

if ! docker info >/dev/null 2>&1; then
  echo "Docker Desktop を起動します..."
  open -a Docker
fi
for i in $(seq 1 60); do
  if docker info >/dev/null 2>&1; then break; fi
  echo "Docker の起動を待っています... (${i}/60)"
  sleep 2
done
if ! docker info >/dev/null 2>&1; then
  echo "エラー: Docker が起動しません。起動を中止します。"
  exit 1
fi

for s in "${SERVICES[@]}"; do
  if [ -f ~/server/$s/docker-compose.yml ]; then
    echo "起動: $s"
    (cd ~/server/$s && docker compose up -d)
  fi
done
echo "サービスを起動しました"
```

`~/server/scripts/down.sh`

```bash
#!/bin/bash
set -u
SERVICES=(homepage apps)
for s in "${SERVICES[@]}"; do
  if [ -f ~/server/$s/docker-compose.yml ]; then
    echo "停止: $s"
    (cd ~/server/$s && docker compose down)
  fi
done
echo "サービスを停止しました"
```

`~/server/scripts/status.sh`

```bash
#!/bin/bash
echo "===== Tailscale ====="
tailscale ip -4 2>/dev/null || echo "!! Tailscale 未接続"
echo ""
echo "===== Docker ====="
if docker info >/dev/null 2>&1; then
  docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
else
  echo "!! Docker Desktop が起動していません"
fi
echo ""
echo "===== 公開ポート（100.x.y.z: で始まれば正常 / *: なら異常）====="
lsof -iTCP -sTCP:LISTEN -n -P 2>/dev/null | grep com.docke | awk '{print $9}' | sort -u
```

| 設計のポイント | 理由 |
| --- | --- |
| up.sh は Tailscale を最大60秒待つ | Tailscale より先に Docker がコンテナを起こすと、まだ存在しない `100.x.y.z` にバインドできず失敗する |
| up.sh は Docker も最大120秒待ち、止まっていれば `open -a Docker` | 再起動後に Docker が未起動だった事例（10月9日）への対策 |
| `set -u` | 未定義の変数を使ったら止める安全装置 |
| up は起動順、down はその逆順 | サービスを足したら `SERVICES` に追記する（同じ compose に足した場合は不要） |
| status.sh の最後の欄 | 公開ポートを一覧にし、`*:` が紛れていないか一目で分かる |
| bash で動く | zsh のエイリアスは効かない。tailscale はラッパー（5-4）が前提 |

## 8-2. 日常の操作

| やりたいこと | コマンド |
| --- | --- |
| 状態を確認 | `~/server/scripts/status.sh` |
| 全部起動 | `~/server/scripts/up.sh` |
| 全部停止（Mac は動いたまま） | `~/server/scripts/down.sh` |
| 電源を切る | `~/server/scripts/down.sh && sudo shutdown -h now` |
| 再起動（手元でログインできるとき） | `~/server/scripts/down.sh && sudo shutdown -r now` |
| 再起動（SSH から。ログイン画面で止めない） | `~/server/scripts/down.sh && sudo fdesetup authrestart` |
| ポータルだけ再起動 | `cd ~/server/homepage && docker compose restart && cd ~` |
| nginx だけ再起動 | `cd ~/server/apps && docker compose restart apps && cd ~` |
| ログを見る | `cd ~/server/apps && docker compose logs --tail=40 <サービス名> && cd ~` |
| ポータルのタイルを編集 | `nano ~/server/homepage/config/services.yaml`（保存は `Ctrl+O` → Enter → `Ctrl+X`） |
| 画面だけ消す | `pmset displaysleepnow`（`Control+7`） |

今後 DB を使うアプリ（Immich やバス予約）が入ると、サービスを止めずに電源を切ると DB が壊れることがあります。**必ず `down.sh` を先に**、を習慣にします。

## 8-3. 電源を入れたときの手順

1. 本体底面の背面寄りの角にある電源ボタンを押す
2. HDMI のモニターとキーボードで `youruser` にログインする（FileVault のため必須。これをしないと何も起動しない）
3. 1〜2分待つ（Tailscale と Docker Desktop が自動で立ち上がる）
4. `~/server/scripts/up.sh && ~/server/scripts/status.sh` を実行する（`restart: unless-stopped` で自動復帰することも多いが、バインド失敗を避けるため毎回実行する）
5. iPhone の「倉庫」を開いて確認する
