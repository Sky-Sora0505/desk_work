# Docker の設計と規約

コンテナを足すときに守る決まりと、フォルダ構成・compose・nginx の中身です。compose とスクリプトの実物は `compose/` と `scripts/` にあります。

コンテナは Docker Desktop 上で動き、compose ファイルは `~/server/apps/` と `~/server/homepage/` の2つです。アプリを足すときは、この章の規約に従います。

## 6-1. 共通規約

| 規約 | 内容 | 理由 |
| --- | --- | --- |
| エンジン | Docker Desktop（既に入っていたため。OrbStack は不採用） | 2つ入れると競合する |
| 公開ポート | `"100.x.y.z:<外>:<中>"` の形だけ。新アプリは原則 `ports` なしで nginx 配下へ | IP を省くと LAN 全体に公開され、macOS の FW では止められない |
| 再起動ポリシー | `restart: unless-stopped` | Docker が立ち上がれば自動で戻る |
| 実行ユーザー | `user: "501:20"` または非 root 版イメージ | 乗っ取られても被害を小さくする |
| ファイルシステム | 自作アプリは `read_only: true` ＋ `tmpfs: [/tmp]` | 書けるのはデータフォルダと一時領域だけ |
| マウント | データは bind mount（Docker 管理ボリュームを使わない）。設定や資材は `:ro` | `docker system prune` などの誤操作でも消えず、バックアップ対象がファイルとして見える |
| イメージ | 公式イメージのみ。タグを固定。自作は `local/<名前>:<版>` | 気づかないうちに中身が変わるのを防ぐ |
| DB | アプリごとに専用。ホストに公開しない | 共有すると障害と権限が連鎖する |
| 秘密情報 | `.env`（権限 600）に置き、compose では `${変数名}` で参照 | GitHub に上げないため |
| Docker ソケット | `/var/run/docker.sock` をコンテナに渡さない | ソケットは全コンテナを操作できる鍵で、実質 root 権限 |
| アプリの URL 名 | 半角英小文字・数字・ハイフンのみ | nginx のパスやフォルダ名にそのまま使う |

## 6-3. `~/server/homepage/docker-compose.yml`

```yaml
services:
  homepage:
    image: ghcr.io/gethomepage/homepage:v2.4.0
    container_name: homepage
    restart: unless-stopped
    ports:
      - "100.x.y.z:3000:3000"
    volumes:
      - /Users/youruser/server/homepage/config:/app/config
    environment:
      HOMEPAGE_ALLOWED_HOSTS: "100.x.y.z:3000,your-mac.your-tailnet.ts.net"
      PUID: 501
      PGID: 20
```

## 6-4. `~/server/apps/docker-compose.yml`

チャットで渡した内容をつなぎ合わせたものです。**実機のファイルを正**とし、引っ越しのときに差分を確認します。

```yaml
services:
  apps:
    image: nginxinc/nginx-unprivileged:1.30.5-alpine3.24
    container_name: apps-static
    restart: unless-stopped
    depends_on:
      - kvstore
    ports:
      - "100.x.y.z:8081:8080"
    volumes:
      - /Users/youruser/server/data/apps/static:/usr/share/nginx/html:ro
      - /Users/youruser/server/apps/nginx/default.conf:/etc/nginx/conf.d/default.conf:ro

  kvstore:
    build: ./kvstore
    image: local/kvstore:1.0.0
    container_name: apps-kvstore
    restart: unless-stopped
    user: "501:20"
    read_only: true
    tmpfs:
      - /tmp
    environment:
      TZ: Asia/Tokyo
      KV_PORT: "8080"
      KV_DB_PATH: /data/kvstore.db
      KV_MAX_VALUE_BYTES: "8388608"
      KV_HISTORY_LIMIT: "30"
      KV_BACKUP_DIR: /data/backup
      KV_BACKUP_KEEP: "10"
      KV_ERROR_DETAIL: "false"
    volumes:
      - /Users/youruser/server/data/kvstore:/data
    healthcheck:
      test:
        - CMD
        - bash
        - -c
        - >-
          exec 3<>/dev/tcp/127.0.0.1/8080
          && printf 'GET /health HTTP/1.0\r\nHost: localhost\r\n\r\n' >&3
          && grep -q '"ok":true' <&3
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 20s

  dictionary:
    build: ./my-dictionary
    image: local/my-dictionary:1.0.0
    container_name: apps-dictionary
    restart: unless-stopped
    user: "501:20"
    read_only: true
    tmpfs:
      - /tmp
    environment:
      TZ: Asia/Tokyo
    volumes:
      - /Users/youruser/server/data/dictionary:/data
```

| ポイント | 説明 |
| --- | --- |
| `apps` の内側ポートが 8080 | 非 root 版 nginx は 1024 未満のポートを使えないため |
| `kvstore` と `dictionary` に `ports` がない | 外から直接届かず、同じ compose 内のネットワークで nginx からだけ届く |
| `healthcheck` | 30秒ごとに `/health` を叩く。`status.sh` で `(healthy)` と表示される。My辞書は Dockerfile 側で定義されているとみられる（`(healthy)` になるため） |
| `build` + `image` | `docker compose build <サービス名>` で、書いた名前と版のイメージができる |
| KV の Dockerfile | マルチステージ。Maven は Docker の中で動くので Mac に Java や Maven は不要。実行イメージ `eclipse-temurin:21-jre` を `21.0.x_y-jre` に固定したかは**要確認** |

## 6-5. `~/server/apps/nginx/default.conf`（構造）

nginx は、URL の頭で行き先を振り分けます。上から順に評価されるのではなく、**一致する中で最も長い `location`** が使われます。バックエンドの `location` は「静的アプリ」のコメント行より上に置く約束です（辞書の追加スクリプトはこのコメントを目印に差し込んだ）。

| location | 行き先 | 内容 |
| --- | --- | --- |
| `/api/` | `http://kvstore:8080` | KVストア。`/api` を外して中継（`/api/health` → `/health`）。502/503/504 は `@kvstore_down`、413 は `@too_large` で日本語 JSON に差し替え |
| `= /my-dictionary` | — | `/my-dictionary/` へ 301 リダイレクト |
| `/my-dictionary/` | `http://dictionary:8080` | `/my-dictionary/` を外して中継。`client_max_body_size 20m`（CSV 取り込み用）。停止時は `@dictionary_down` |
| `/` | `/usr/share/nginx/html` | `try_files $uri $uri/ =404`。ディレクトリ一覧は出さない |

辞書の中継部分は次のとおりです（KVストアの `/api/` も同じ書き方です）。

```nginx
location /my-dictionary/ {
    client_max_body_size 20m;
    resolver 127.0.0.11 valid=30s ipv6=off;
    set $dictionary http://dictionary:8080;
    rewrite ^/my-dictionary/(.*)$ /$1 break;
    proxy_pass $dictionary;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_connect_timeout 3s;
    proxy_read_timeout 30s;
    proxy_intercept_errors off;
    error_page 502 503 504 = @dictionary_down;
}
```

| 書き方 | 理由 |
| --- | --- |
| `resolver 127.0.0.11` ＋ `set $変数` | Docker 内部の DNS で毎回名前を引く。バックエンドが止まっていても nginx 自体は起動でき、起動順に依存しない |
| `proxy_intercept_errors off` | アプリが返したエラー JSON はそのまま通し、nginx 自身が出すエラーだけ差し替える |
| 同じオリジンで中継 | 画面と API が同じ `:8081` なので、ブラウザの CORS 制限にかからない |

変更したら `docker exec apps-static nginx -t` で文法を確かめ、`syntax is ok` と `test is successful` が出てから再起動します。

## 7-2. nginx（apps-static）

| 項目 | 内容 |
| --- | --- |
| 役割 | (1) HTML/CSS/JS だけで完結するアプリの配信、(2) バックエンドへの中継（リバースプロキシ） |
| アプリの置き方 | `~/server/data/apps/static/<アプリ名>/index.html` → `http://100.x.y.z:8081/<アプリ名>/` |
| 実行ユーザー | `uid=101(nginx)`（root ではない） |
| 配信元 | `:ro`（読み取り専用）。nginx が乗っ取られてもアプリを書き換えられない |
| 静的アプリの更新 | ファイルを上書きするだけ。再起動不要 |
| オフライン機能 | 使えない。Service Worker は HTTPS でしか動かず、倉庫は HTTP のため |
| 位置情報 | 同じ理由で iPhone Safari では使えない（coupon-checker が Tailscale Serve を使う理由） |
