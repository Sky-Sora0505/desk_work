# Docker のしくみ

イメージ・コンテナ・ボリュームの関係と、この倉庫での使い方です。

## 17-2. Docker：プログラムは中、データは外

| 言葉 | 意味 | たとえ |
| --- | --- | --- |
| イメージ | アプリ本体と、動かすのに必要な最小限の部品をひとまとめにした「ひな形」。中身は変わらない | 部屋の設計図 |
| コンテナ | イメージから作って動かしている実体。使い捨てで、作り直すと中身は元に戻る | 設計図から建てた部屋 |
| ボリューム / バインドマウント | Mac のフォルダを、コンテナの中の決まった場所に見せる「窓」 | 部屋の外にある倉庫への窓 |
| Dockerfile | イメージの作り方を書いた手順書 | 設計図の描き方 |
| docker-compose.yml | どのイメージを、どのポートと窓で、どう動かすかをまとめた設定ファイル | 建物全体の配置図 |
| レジストリ | イメージの置き場所（Docker Hub、ghcr.io など）。`pull` でここから取ってくる | 設計図の図書館 |
| タグ | イメージの版の名前（`v2.4.0` など）。`latest` は「その時点の最新」で中身が変わるので使わない | 設計図の版数 |

コンテナは作り直すと中身が消えます。そこで、消えたら困るもの（DB、設定、自作アプリのファイル）は Mac 側のフォルダに置き、窓でつなぎます。compose の `volumes:` は「左が Mac 側、右がコンテナ側」です。

| コンテナ | プログラム（イメージの中） | Mac 側のフォルダ → コンテナの中 |
| --- | --- | --- |
| `homepage` | Homepage 本体 | `~/server/homepage/config` → `/app/config` |
| `apps-static` | nginx 本体 | `~/server/data/apps/static` → `/usr/share/nginx/html`（読み取り専用）、`~/server/apps/nginx/default.conf` → `/etc/nginx/conf.d/default.conf`（読み取り専用） |
| `apps-kvstore` | 自作の Java プログラム（`docker compose build` でイメージにした） | `~/server/data/kvstore` → `/data` |
| `apps-dictionary` | 自作の Node.js プログラム（同上） | `~/server/data/dictionary` → `/data` |

nginx は「配達員」です。Java Silver 17 ドリルのような HTML だけのアプリは Mac 側のフォルダにあり、nginx はそれを配っているだけなので、ファイルを置き換えれば更新できます。一方、KVストアと My辞書は自分で作ったプログラムなので、イメージを作り直します（`build`）。

| 覚えておくこと | 説明 |
| --- | --- |
| `ports: "100.x.y.z:8081:8080"` | 「Mac の 100.x.y.z の 8081 番に来たものを、コンテナの 8080 番へ渡す」。左の IP を省くと、Mac の全部の住所（家の Wi-Fi 側も）で受けてしまう |
| `ports` を書かないコンテナ | Mac の外からは届かない。同じ compose の中のコンテナ同士だけが、サービス名（`kvstore`、`dictionary`）を宛先にして話せる |
| 同じ DB でも見る人で宛先が変わる | コンテナからは `db:5432`、Mac からは `localhost:15432` のように、ホスト名とポートが変わる |
| `down` と `down -v` | `down` はコンテナを消すだけでデータは残る。`-v` は Docker 管理のボリュームも消す |
| `restart` と `up -d` | compose を書き換えたときは `up -d`。`restart` では反映されない |
