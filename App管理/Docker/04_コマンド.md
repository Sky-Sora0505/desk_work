# Docker のコマンド

この倉庫で使う Docker のコマンドと、名前の由来です。

## 15-1. Docker（コンテナを動かす）

`docker compose` は「今いるフォルダの `docker-compose.yml`」を対象にします。先に `cd ~/server/apps` などで移動します。compose（組み立てる）は、複数のコンテナをまとめて扱うという意味です。

| コマンド | 意味 | 語源・補足 |
| --- | --- | --- |
| `docker compose up -d` | 定義どおりに起動（変更があれば作り直す） | `-d` = detached（切り離して裏で動かす） |
| `docker compose down` | コンテナとネットワークを消す。bind mount のデータは残る | `-v` を付けるとボリュームも消すので使わない |
| `docker compose restart <サービス>` | 作り直さずに再起動 | 設定ファイルを読み直させるとき。compose の変更は `up -d` でないと反映されない |
| `docker compose build <サービス>` | Dockerfile からイメージを作る | 自作アプリのコードを変えたら必要 |
| `docker compose logs --tail=40 <サービス>` | 最後の40行のログ | `-f` を足すと流れ続ける（follow、`Ctrl+C` で抜ける） |
| `docker compose config --services` | compose を解釈してサービス名を出す | 文法チェック代わり。`--services` なしで展開後の全文 |
| `docker compose ps` | この compose のコンテナ一覧 | ps = process status（Unix の ps から） |
| `docker ps` | 動いている全コンテナ | `-a` で止まっているものも |
| `docker exec <コンテナ> <コマンド>` | 動いているコンテナの中で実行 | exec = execute。例 `docker exec apps-static nginx -t` |
| `docker inspect <コンテナ>` | 設定の詳細（JSON） | `--format '{{range .Mounts}}{{.Source}}{{"\n"}}{{end}}'` でマウント元だけ |
| `docker logs <コンテナ> --tail 20` | compose を使わずコンテナ名でログ | どのフォルダにいても使える |
| `docker info` | Docker が応答するか | スクリプトでは `>/dev/null 2>&1` で結果だけ使う |
| `docker run --rm hello-world` | Docker が動くかの最小テスト | `--rm` = 終わったら消す |
| `docker image ls` / `docker system df` | イメージ一覧 / ディスク使用量 | df = disk free |
| `docker image prune` | 使われていないイメージを消す | データは消えない。`system prune` は範囲が広いので本人が判断 |
| `open -a Docker` | Docker Desktop を起動 | macOS の `open`、`-a` = application |
