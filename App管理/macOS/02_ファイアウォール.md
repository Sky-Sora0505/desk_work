# ファイアウォールの許可アプリ

アプリごとの許可の考え方です。

## 5-6. ファイアウォールの許可アプリ（10月2日に棚卸し）

macOS のファイアウォールは「アプリごとに、外からの接続を受けてよいか」を持っています。一覧を見て、次のように判断しました。

| アプリ | 判断 | 理由 |
| --- | --- | --- |
| `/usr/bin/python3` | 削除済み | CP3 の疎通テストで一時的に許可したもの |
| Homebrew 版 Python 3.14 | 削除済み | テストで許可された可能性。開発で外から接続される必要がない |
| Homebrew 版 `java`（openjdk@21） | 「ブロック」に戻す（**要確認**） | Mac に直接入れた Java で、外から接続される必要がない。KVストアの Java はコンテナの中で動くので、ブロックしても影響しない |
| Docker | 許可（必要） | サーバーの土台。コンテナの通信はここを通る |
| `io.tailscale…` | 許可（必要） | 外からの入口 |
| sshd-auth / sshd-keygen-wrapper | 許可（必要） | SSH。鍵認証のみ |
| smbd | 残してよい | ファイル共有をオフにしているので待ち受けていない。外付けドライブ導入時に使う |
| 別の VPN アプリ | **要確認** | Tailscale と別の VPN を同時に使うと競合する。使っていなければアンインストール、使うなら Tailscale 利用時はオフ |
| cupsd / ruby / replicatord / remoted | 放置 | macOS 標準 |
| 普段使うアプリ（音楽・ゲーム・ブラウザなど） | 許可のまま | 自分で入れて使っているもの |

| 画面下の設定 | 推奨 |
| --- | --- |
| 内蔵ソフトウェアが外部からの接続を受け入れるのを自動的に許可 | オンのまま（macOS 標準機能） |
| ダウンロードされた署名付きソフトウェアが外部からの接続を受け入れるのを自動的に許可 | **オフを推奨**（任意）。署名付きアプリでも初回に確認が出るようになり、「知らないうちにポートが開いていた」を防げる |

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --listapps
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --remove /usr/bin/python3
```

変更したら、`~/server/scripts/status.sh` と `curl -s http://100.x.y.z:8081/api/health; echo` でサーバーが無事か確かめます。
