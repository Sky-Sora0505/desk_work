## 13-4. ローカル LLM

ローカルで動かせるのは重みが公開されているモデルだけです。Claude（Sonnet など）は重みが公開されていないので、どんなハードウェアでもローカルでは動きません。

| 項目 | 検討結果 |
| --- | --- |
| 上限のモデル | Gemma 4 の 12B。24GB のメモリを Immich の機械学習と分け合うことを考えるとここが実用上の上限（Gemma 4 は E2B / E4B / 12B / 26B A4B / 31B の構成） |
| 実行形式 | GGUF より MLX（Apple Silicon で 1.5〜1.7 倍速い） |
| 動かし方 | Docker の中ではなく Mac に直接（Ollama や LM Studio）。Docker 経由だと GPU（Metal）が使えない |
| 公開するなら | `127.0.0.1` に待ち受け、必要なら nginx 経由か Tailscale Serve。`0.0.0.0` 待ち受けは LAN に公開されるので不可 |
| 注意 | 推論中は発熱が大きい。温度は `pmset -g therm` |
| 買い替え | 本格的に使うなら48GB が望ましい（メモリは後から増やせない）。M5 / M6 世代の Mac mini の発表を注視 |
| 動機 | API 利用料をかけず、機密情報を外部に出さないこと |

Gemma 4（2026年4月公開、Apache 2.0）は「擬似的な LLM」ではなく、重みファイルを丸ごとダウンロードして自分の Mac で動かす本物の LLM です。24GB のうち GPU に回せるのは既定で7割ほど（約17〜18GB）なので、次の見立てになります。数字は検討時（8月30日）の目安で、実測ではありません。

| モデル（Q4 量子化） | 概算サイズ | 24GB での見立て |
| --- | --- | --- |
| E4B | 約10GB | 余裕 |
| 12B | 7〜8GB | 本命。20〜25 トークン/秒 前後 |
| 26B A4B（MoE、実働 4B） | 15GB 前後 | 載る |
| 31B | 18〜19GB | 単体でぎりぎり。他のサービスと同居は不可 |

品質は、31B でも Claude とは差があります（長い文脈の追跡、複雑なデバッグ、微妙な指示の解釈）。使い分けは「仕事のコーディングや AWS は Claude、社外に出せない情報の要約・分類・下書きや、大量に回すと API 料金が痛い処理はローカル」です。最初の一歩は、Ollama で Gemma 4 12B を入れて速度と品質を体感することです。
