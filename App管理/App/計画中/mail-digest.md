## 13-5. 重要メール抽出（mail-digest）の詳細

3〜4個の個人 Gmail の1日分を集め、重要そうなものを点数の高い順に並べるアプリです。要約はせず、キーワードが多く入っているものほど上に出します。AI も API 課金も使いません。

| 項目 | 決めたこと |
| --- | --- |
| 言語 | **Python**（本人の希望。今後の学習の参考に、簡単で分かりやすく） |
| 対象 | 個人の Gmail を3〜4アカウント。会社のアカウントは管理者に API を止められている可能性があるので対象外 |
| Proton Mail | 本人が検討中。「厳しければ見送ってよい」とのことで、初版の対象外 |
| 本文の扱い | 一覧には件名・差出人・点数・該当キーワードだけ保存。「全文を見る」を押したときに Gmail API から取りに行く。サーバーに本文を残さない |
| 採点 | 単語の重み × 出現数。件名は3倍、1単語は最大3回まで数える（連呼する広告対策）、差出人のドメインで加点、足切り点 |
| 取得時の絞り込み | `newer_than:1d -category:promotions -category:social` |
| 設定 | キーワードと重み、差出人ルール、足切り点、対象アカウントを画面から編集できるようにする |
| 権限 | Gmail API の読み取り専用（`gmail.readonly`）だけ。漏れても「読まれる」だけで送信・削除はされない |
| 実行 | 毎朝7時に自動実行し、結果を SQLite に保存。倉庫の「今日の重要メール」に点数順で表示 |
| 状態 | 設計まで。未着手 |

| キーワードの初期値 | 点数 |
| --- | --- |
| 至急 / 緊急 | 10 |
| 請求 / 支払 | 8 |
| 面接 / 選考 | 8 |
| 期限 / 締切 | 6 |
| 研修 / 重要 | 5 |
| 確認 | 3 |
| セール / キャンペーン | -5 |
| 配信停止 / メルマガ | -10 |

最大の落とし穴は認証の期限です。Google Cloud 側の設定が「テスト」のままだと、認証が7日で切れます。しかも目立ったエラーが出ないので、「重要なメールが来なかった日」と区別がつきません。公開ステータスを「本番環境」にし、認証切れを画面に表示する作りにします。

ファイル構成は KVストアと同じ層構造にします（`config.py` 設定、`errors.py` エラー定義、`models.py` データの型、`gmail_client.py` Gmail との通信、`scorer.py` 採点、`repository.py` SQLite、`service.py` 業務ルール、`web.py` 画面と API、`main.py` 組み立て）。Java と Python で同じ設計をどう書き分けるかを見比べられます。
