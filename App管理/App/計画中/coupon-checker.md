## 13-2. coupon-checker（近所の店のクーポン有無チェッカー）

現在地から半径500m以内の店で、PayPay・Vpass・イオン・dポイントなどのクーポンが「あるかどうか」だけを表示する Web アプリです。クーポンの中身は各アプリで自分で取得し、このアプリには「店名と決済手段」を手動で登録します。

| 項目 | 決定内容 |
| --- | --- |
| 技術 | Java 21、Spring Boot、MyBatis、PostgreSQL 17、Flyway（別コンテナ）、WireMock（結合試験用のダミー） |
| DB の権限分離 | 管理者・スキーマ所有者（Flyway）・アプリ用（読み書きのみ）の3つに分ける（業務と同じやり方） |
| 周辺店舗の取得 | OpenStreetMap の Overpass API（外部通信はここだけ）。登録した店名が周辺店舗名に含まれるかで照合 |
| 決済手段の入力 | プルダウン（PayPay→Vpass→イオン→dポイントの順、過去に使った手段を自動で追加）＋「その他」で自由入力 |
| 環境分離 | テスト（`coupon-test`、`127.0.0.1:18081`、DB `127.0.0.1:15433`）と本番（`coupon-prod`、`127.0.0.1:18080`、DB `127.0.0.1:15432`）を compose プロジェクト名・DB・ボリュームで分離。同じイメージを使う |
| 公開 | `tailscale serve --bg --https=8443 http://127.0.0.1:18080` → `https://your-mac.your-tailnet.ts.net:8443`。iPhone Safari は HTTP で位置情報を渡さないため |
| 試験 | 単体試験59項目、結合試験57項目＋本番受入れ8項目。全部合格してから `git tag v1.0.0` を打ち本番へ |
| 運用 | 毎日 3:00 に DB バックアップ、月次でイメージ更新と脆弱性スキャン、監視は通知ではなく「どこで失敗したか」を画面の「状況」タブで表示 |
| コードの置き場 | My_BOX の `coupon-checker/`。秘密情報は `.gitignore` / `.dockerignore` で除外 |
| 実装 | AI に任せる方針。コードレビューは本人が固定のチェックリストで |

資料は要件定義書・設計仕様書・画面設計書・手順書・単体試験仕様書・結合試験仕様書・試験計画書・パラメータシート・運用手順書・セキュリティ設計の10本です（claude.ai のチャット「近所の店舗クーポン確認アプリ」）。資料では作業フォルダが `~/apps/coupon-checker` と `~/apps/My_BOX/coupon-checker` の2通り書かれているので、引っ越し後の配置（14章）に合わせて統一します。

導入の前に、ポートの重なりを片付けます。本番 DB に使う `127.0.0.1:15432` は、Java 演習用の DB（19-3）が既に `15432` を使っています。どちらかの番号を変えます。また、coupon-checker の設計を始めたときに確認した点が2つあります。`curl` は「ターミナルから URL を開いて結果を文字で受け取る道具」です。店が OpenStreetMap に載っているかは、ブラウザで openstreetmap.org を開いて店名を探せば確かめられます（Google マップは座標を調べる補助に使える）。普段使う地域では問題なく載っていることを本人が確認済みです。
