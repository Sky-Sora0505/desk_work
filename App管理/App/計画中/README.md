## 13-6. フラッシュカードと Garmin の補足

| アプリ | 難易度 | 決めたこと・分かったこと |
| --- | --- | --- |
| フラッシュカード | 低（最初に作るのに向く） | デッキを分ける（Java / 基本情報 / AWS CLF-C02）。進捗はサーバーに保存する。「間違えた問題ほど頻繁に出す」間隔反復を入れると効果が大きい。問題は CSV や JSON で取り込む形にするとデッキの追加が楽 |
| Garmin の体調管理 | 高（時計を買ってから） | Garmin の公式 Health API は法人向けで、個人は基本的に使えない。取り方は、(1) Garmin Connect から手動で書き出す、(2) iPhone の「ヘルスケア」に同期してから書き出す（公式の経路で安全）、(3) 非公式ライブラリで自動取得（規約上グレーで、仕様変更で突然壊れ、Garmin のパスワードをサーバーに置く必要がある） |

メールや健康データが入ると、サーバーの中身の重要度が一段上がります。そのため、普段外して保管するバックアップ用の Drive B は暗号化（APFS 暗号化）を推奨します。Drive B は自動起動と関係がないので、暗号化しても不便はほとんどありません。

## 13-7. iPhone のボタン1つでオン・オフする方法

| レベル | 何を切り替えるか | 方法 | 状態 |
| --- | --- | --- | --- |
| A | 接続そのもの | iPhone の Tailscale アプリのスイッチ。オフにすれば自宅サーバーへの経路が完全に切れる。「使うときだけオン」が最も強い | 今すぐ使える |
| B | サービスの起動・停止 | ショートカット App の「SSH 経由でスクリプトを実行」で `~/server/scripts/up.sh` / `down.sh` を呼び、ホーム画面にアイコンを置く | 未設定。ショートカット専用の SSH 鍵を作って `authorized_keys` に足す必要がある |
| C | 外部公開 | `tailscale funnel` のオン・オフ | **使わない**（最初の相談で出た案。その後、インターネットには一切公開しない方針に決めた） |

## 13-8. 参考にできる公開リポジトリについて

「この構成をそのまま網羅した公式リポジトリはあるか」という話題も出ました。Mac mini・Tailscale・Docker の組み合わせをそのまま網羅したものは無く、世界中の人が自宅サーバー（HomeLab）の構成と `docker-compose.yml` を公開しているリポジトリを部分的に参考にする、というのがそのときの整理です。この倉庫の構成は、この文書と `~/server` が一次資料です。
