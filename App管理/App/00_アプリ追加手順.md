# アプリ追加の標準手順

新しいアプリを倉庫に載せるときの型と手順です。

新しいアプリは「8081 の nginx 配下にパスを切って置き、独自の公開ポートを持たせない」のが標準です。ACL も公開ポートも変えずに済み、既存アプリと同じ起動・停止スクリプトで管理できます。

## 9-1. どの型で追加するか

| 型 | 対象 | 例 | やること |
| --- | --- | --- | --- |
| A. 静的アプリ | HTML/CSS/JS だけで完結し、保存が不要 | 動作確認ページ | フォルダを置くだけ |
| B. 静的アプリ＋KVストア | 画面だけのアプリで、進捗などを端末間で共有したい | Java Silver 17 ドリル | 保存部分を `/api/kv/` に向けて置く |
| C. 専用バックエンド付き | 独自の API や DB が必要 | My辞書 | compose にサービス追加＋nginx に `location` 追加 |
| D. HTTPS 必須 | 位置情報・オフライン（Service Worker）が必要 | coupon-checker（計画） | `127.0.0.1` にバインドし、`tailscale serve --https=8443` で公開。ACL に `tcp:8443` を追加 |

## 9-2. 共通の進め方

1. **テスト環境で試す**。単体・結合試験を仮想環境で行い、全部合格してから本番の倉庫に登録する（本人が決めた進め方）
2. **止めて控えを取る**：`~/server/scripts/down.sh` → `docker-compose.yml` と `default.conf` を `.bak-$(date +%Y%m%d)` でコピー
3. **配置する**（型ごとに 9-3〜9-5）
4. **確かめる**：`docker compose config --services`（compose の文法）、`docker exec apps-static nginx -t`（nginx の文法）
5. **ビルドして起動**：`cd ~/server/apps && docker compose build <サービス名> && cd ~` → `~/server/scripts/up.sh` → （待ってから）`~/server/scripts/status.sh`
6. **試験する**：curl で API を叩き、画面を開く。既存アプリが壊れていないか（`/api/health` と `/java-silver17/` が 200）も確かめる
7. **ポータルに登録**：`services.yaml` の該当グループにタイルを追記
8. **負のテスト**：iPhone の Tailscale をオフにし、モバイル回線で**開けないこと**を確認
9. **GitHub に記録**：コードをコミット（データフォルダは上げない）

公開ポートが 3000 と 8081 の2つのままであること、新しいコンテナが `Up`（healthcheck があれば `(healthy)`）であることが合格条件です。

## 9-3. 型 A：静的アプリ

```bash
mkdir -p ~/server/data/apps/static/<アプリ名>
cp ~/Downloads/<ファイル名>.html ~/server/data/apps/static/<アプリ名>/index.html
curl -s -o /dev/null -w "%{http_code}\n" http://100.x.y.z:8081/<アプリ名>/
```

`200` が出れば成功です。nginx の再起動は不要です。ダウンロードは **Mac mini 上のブラウザで**行います（iPhone に保存しても届きません）。ファイル名が `index (1).html` のように変わることがあるので、`ls -lt ~/Downloads/*.html | head` で確かめます。

## 9-4. 型 B：静的アプリ＋KVストア

Claude のチャットで作ったアプリは、保存に `window.storage`（チャット専用）や `localStorage` を使っています。その呼び出し口だけを KVストアへの読み書きに差し替え、アプリ本体は書き換えません。

| 差し替えの部品（`kvstore-java/frontend/src/`） | 役割 |
| --- | --- |
| `kv-client.js` | サーバーとの通信。タイムアウトと楽観的ロック（`X-Expected-Revision`） |
| `storage-adapter.js` | `window.storage` をサーバー保存に差し替える。読み込みに失敗したら保存を止める |
| `notice.js` | 日本語のエラーバナー |
| `main.jsx` | 起動処理。esbuild で単体 HTML にまとめる |

キーはアプリごとに分けます（`アプリ名:用途:版`）。他のアプリからも次のように使えます。

```javascript
await fetch("/api/kv/myapp%3Adata", { method: "PUT", body: JSON.stringify(data) });
const r = await fetch("/api/kv/myapp%3Adata");
```

## 9-5. 型 C：専用バックエンド付き（My辞書で確立した形）

| 手順 | 内容 |
| --- | --- |
| 1. コードを置く | `~/server/apps/<アプリ名>/`。単体用の `docker-compose.yml` が付いていたら削除 |
| 2. データフォルダ | `mkdir -p ~/server/data/<アプリ名>` |
| 3. 絶対パスを相対パスに | 画面が `/api/…` のように `/` 始まりで書いていると、KVストアの `/api/` に届いてしまう。`api/…` `sw.js` `./` のように直す。直した後 `grep` で絶対パスが残っていないか確認 |
| 4. compose に追記 | 6-4 の `dictionary` と同じ形（`build`、`image: local/<名前>:1.0.0`、`user: "501:20"`、`read_only`、`tmpfs`、データの bind mount、**`ports` なし**） |
| 5. nginx に追記 | 6-5 の `/my-dictionary/` と同じ形を「静的アプリ」のコメントより上に。`= /<名前>` の 301 も忘れずに |
| 6. 起動と試験 | 9-2 の 4〜8 |

辞書のときは、nginx への差し込みを Python スクリプト（`insert_nginx_snippet.py`）で行いました。「静的アプリ」のコメント行を探してその直前に挿むだけで、既に入っていれば何もしない作りです（2回実行しても二重にならない）。Claude Code に移った後は、Claude Code が直接ファイルを編集するのでこの仕組みは不要です。

## 9-6. 保留中の「独立ポート型」

Immich（2283）やバス予約アプリ（8090）のように、公式の構成が独自ポートを前提にしているものは、例外として `100.x.y.z:<ポート>` にバインドして公開します。その場合は `~/server/<サービス名>/` に別 compose を作り、`up.sh` と `down.sh` の `SERVICES` に追記します。ACL にはそのポートが既に入っています。
