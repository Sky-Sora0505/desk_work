# kvstore（進捗の保存サーバー）

アプリの進捗をサーバーに保存し、iPhone と Mac で続きから使えるようにする自作サーバーです（Java 21 + SQLite）。

> **ソースはまだこのフォルダに入っていません。** Mac mini の `~/server/apps/kvstore/` にあります。`tools/sync.sh import` で `code/` に取り込めます（`tools/README.md`）。

## 7-3. KVストア（apps-kvstore）

ブラウザの中（localStorage）にあった進捗を、サーバーに移すための小さな保存サーバーです。「キーと値」の組を保存するだけの単純な作りなので、他の自作アプリからも使えます。

**技術構成**

| 項目 | 内容 |
| --- | --- |
| 言語 | Java 21。フレームワークなし、依存ライブラリは SQLite ドライバ（sqlite-jdbc）のみ |
| DB | SQLite（`/data/kvstore.db`、ホスト側 `~/server/data/kvstore/`） |
| メモリ | 約61MB（`-Xms16m -Xmx128m -XX:+UseSerialGC`） |
| 歴史 | 最初 Node.js（外部パッケージなし、1キー1 JSON ファイル）で試作 → 添削で問題13件を指摘 → 本人の希望（Java・オブジェクト指向・日本語エラー・SQL）で書き直し |
| テスト | 約70項目（正常系17・異常系20・同時実行2・障害時5・画面側の2台模擬14・nginx 経由10 ほか）。同じリビジョンで10件同時に書くと1件だけ成功、9件が409 |

**層構造**（`kvstore/src/main/java/kvstore/`）

| 層 | クラス | 責任 |
| --- | --- | --- |
| HTTP 層（`http/`） | ApiServer、Router、KvController、HealthController、AdminController | URL の振り分け。例外はすべて ErrorResponder で日本語エラーに変換 |
| 業務層（`service/`） | KvService、HealthService、BackupService | 「無ければ404」「競合なら409」などの判断 |
| データ層（`repository/`） | KvRepository（インターフェース）、SqliteKvRepository、Database | SQL はすべてここ。接続・トランザクション・エラー分類は Database |
| その他 | `config/`、`error/`、`domain/`、`support/`、`Main.java`、`resources/schema.sql` | 環境変数の検証、エラーコードと発生箇所、キー等の型、JSON・ログ、組み立て、テーブルと履歴トリガー |

**API**（すべて `http://100.x.y.z:8081/api` から）

| メソッド | パス | 動作 |
| --- | --- | --- |
| GET | `/health` | 稼働確認。DB に実際に問い合わせる（`"status":"正常"`、`"database":"接続OK"`） |
| GET | `/kv?prefix=xxx` | キーの一覧（値は含まない） |
| GET | `/kv/{key}` | 値の取得。`ETag` ヘッダにリビジョン |
| GET | `/kv/{key}/meta` | 更新情報だけ（軽い） |
| PUT | `/kv/{key}` | 保存。本文がそのまま値になる |
| DELETE | `/kv/{key}` | 削除（削除前の値は履歴に残る） |
| GET | `/kv/{key}/history` | 変更履歴の一覧 |
| GET | `/kv/{key}/history/{revision}` | 過去の値 |
| POST | `/kv/{key}/restore/{revision}` | 過去の値に戻す（戻す直前も履歴に残るので、戻したことも取り消せる） |
| POST | `/admin/backup` | 止めずに一貫性のあるバックアップを作る（`backup/kvstore-<日時>.db`、直近10個） |

| 仕様 | 内容 |
| --- | --- |
| 競合の検出（楽観的ロック） | PUT・DELETE・restore に `X-Expected-Revision` を付けると、現在のリビジョンと一致するときだけ実行。`0` は「まだ無いときだけ」。ヘッダなしは条件なしで上書き |
| 応答の形 | 成功 `{"ok":true,"data":{…}}` / 失敗 `{"ok":false,"error":{"code":"KV-409-01","message":"日本語","where":"発生箇所","errorId":"…"}}` |
| エラーコード | `KV-<HTTPステータス>-<番号>`。例：`KV-409-01`（古いリビジョン）、`KV-409-02`（既に存在）、`KV-500-11`（DB を準備できない）、`KV-502-01`（nginx：保存サーバーに接続不可）、`KV-413-02`（nginx：大きすぎる）。画面側は `KV-CL-xx`（例 `KV-CL-02` サーバー停止中） |
| キーの規則 | 半角英数字と `: . _ -`、200文字以内。命名は `アプリ名:用途:版`。URL では `encodeURIComponent()`（`:` → `%3A`） |
| 上限 | 1件 8MB（Java が日本語で拒否）。さらに大きいと nginx が拒否 |
| 認証 | なし。Tailscale の内側（自分の端末）だけが前提。家族を招待するなら認証の追加を検討 |

**環境変数**（compose の `environment`。変えたら `docker compose up -d` だけで反映、再ビルド不要）

| 変数 | 既定値 | 意味 |
| --- | --- | --- |
| `KV_MAX_VALUE_BYTES` | 8388608 | 1件の上限。増やすなら nginx の `client_max_body_size` も合わせる |
| `KV_HISTORY_LIMIT` | 30 | 1キーあたりの履歴数（0 で履歴なし） |
| `KV_BACKUP_KEEP` | 10 | 残すバックアップ数 |
| `KV_ERROR_DETAIL` | false | true にするとエラー JSON に発生行と詳細が付く。開発中だけ |

値が不正なら、どの変数がどう間違っているかを示して起動を止めます。

**画面側の安全装置**（アプリ本体は書き換えず、保存の受け口だけ差し替えている）

| 画面の表示 | 意味と対処 |
| --- | --- |
| 「他の端末で更新されています」 | 古い画面からの上書きをサーバーが拒否した。データは無事。「再読み込み」を押す |
| 「進捗を読み込めませんでした」 | このまま解いても保存されない（空データで上書きしないための停止）。サーバーを直してから再読み込み |
| 「保存できませんでした」 | 一時的な通信エラー。次の操作で自動的に保存し直す |

別の端末で続きをやるときは、ページを開き直します（iPhone は画面を下に引っ張って再読み込み）。

**エラーコードの一覧**

| コード | HTTP | 画面のメッセージ（要約） | 主な原因 |
| --- | --- | --- | --- |
| KV-400-01 | 400 | キーの形式が正しくありません | 使えない文字、長すぎるキー |
| KV-400-02 | 400 | 検索条件（prefix）の形式が正しくありません | 一覧取得の条件が不正 |
| KV-400-03 | 400 | リビジョン番号の形式が正しくありません | ヘッダや URL の番号が不正 |
| KV-400-04 | 400 | 文字コードが UTF-8 ではありません | 送信データが壊れている |
| KV-400-05 | 400 | URL の形式が正しくありません | URL のエンコードが壊れている |
| KV-400-06 | 400 | 送信データを受信できませんでした | 送信中に通信が切れた |
| KV-404-01 | 404 | データが見つかりません | まだ一度も保存していない（初回は正常） |
| KV-404-02 | 404 | 指定した履歴が見つかりません | 古すぎて削除された履歴を指定した |
| KV-404-03 | 404 | 指定された URL は存在しません | URL の打ち間違い |
| KV-405-01 | 405 | この URL ではその操作はできません | メソッド違い |
| KV-409-01 | 409 | 他の端末で先に更新されています | 古い画面から保存しようとした |
| KV-409-02 | 409 | 他の端末で先にデータが作成されています | 同時に初回保存した |
| KV-413-01 | 413 | データが大きすぎます | 8MB を超えた |
| KV-500-01 | 500 | データベースの処理でエラー | SQL の実行失敗（ログを確認） |
| KV-500-02 | 500 | データベースが破損している可能性 | DB ファイルの破損。バックアップから戻す |
| KV-500-03 | 500 | バックアップの作成に失敗 | 保存先の権限・容量 |
| KV-500-10 / 11 / 12 | — | 設定値が不正 / DB を準備できない / 起動できない | 起動時のみ。環境変数の誤り、フォルダの権限、ポートの重複 |
| KV-500-99 | 500 | 予期しないエラー | プログラムの不具合（ログの発生行を確認） |
| KV-503-01 / 02 | 503 | DB が混み合っている / アクセスできない | 書き込みの集中、ディスクの問題 |
| KV-507-01 | 507 | 保存容量が不足しています | ディスクの空きがない |
| KV-502-01 | 502 | （nginx）KVストアに接続できない | 停止中・起動中 |
| KV-413-02 | 413 | （nginx）データが大きすぎる | 9MB を超える送信 |
| KV-CL-01 | — | （画面）10秒以内に応答がない | 通信状態 |
| KV-CL-02 | — | （画面）サーバーに接続できない | Tailscale がオフ、サーバー停止 |
| KV-CL-03 | — | （画面）想定外の応答 | サーバーの状態を確認 |
| KV-CL-04 | — | （画面）データ保護のため保存を停止中 | 再読み込みする |
| KV-CL-05 | — | （画面）戻ったら他の端末で更新されていた | 再読み込みする |

ログは `cd ~/server/apps && docker compose logs --tail=30 kvstore && cd ~` で見ます。画面に出るエラーID でログを探すと、発生した行まで分かります。

**なぜ Node.js 版をやめて Java で書き直したか**（添削で見つけた13件のうち主なもの）

| 重大度 | 旧 Node.js 版の問題 | Java 版での対応 |
| --- | --- | --- |
| 高 | 後から保存した方が勝つ。iPhone を開いたまま Mac で解き、iPhone で1問解くと Mac の進捗が消える | リビジョン番号による楽観的ロック。古い状態からの保存は 409 で拒否 |
| 高 | 停止信号を処理せず、書き込み途中で強制終了される恐れ | 処理中のリクエストを最大2秒待ってから停止 |
| 高 | 通信にタイムアウトがなく、電波が悪いと画面が固まる | 10秒でタイムアウトし日本語で表示 |
| 中 | エラーが英語の内部メッセージのまま出る。ログが一切ない | 画面には日本語・コード・発生箇所・エラーID。詳細はログへ |
| 中 | 上書き・削除したデータを戻せない | 変更履歴30件、復元、止めずに取れるバックアップ |
| 中 | 保存ファイルが壊れると英語の 500 になるだけ | SQLite のトランザクション。破損は「DB破損」と明示 |
| 低 | `/api` の判定が `/apix` にも一致、UTF-8 の検査なし、イメージの版が未固定 など | それぞれ修正。版番号付きの自作イメージ＋読み取り専用コンテナ |

旧版から引き継いだ良い点は、キーの文字制限（`../` などのパス移動を拒否）、ポートを外に出さない構成、root 以外での実行です。

| 作りの選択 | 理由 |
| --- | --- |
| Java 21 + SQLite | 本人の希望。SQL で履歴・条件付き更新・バックアップを簡潔に書ける |
| フレームワークなし（JDK 標準の HttpServer） | 依存は SQLite ドライバ1つ。メモリ約 61MB（Spring Boot は通常 200MB 超）。攻撃対象になる部品が少ない |
| 仮想スレッド（Java 21） | 1リクエスト1スレッドの分かりやすい書き方のまま、軽く動く |

| 改造したいとき | やること |
| --- | --- |
| URL を増やす | コントローラの `registerTo` に1行（例 `router.get("/kv/{key}/size", this::size);`）と、処理のメソッドを1つ足す |
| 保存先を PostgreSQL などに変える | `KvRepository` を実装したクラスを作り、`Main.java` の1行を差し替える。業務層と HTTP 層は変更不要 |
| Spring の練習にする | `KvService` と `KvRepository` はそのまま使い、`http` パッケージだけ Spring MVC に置き換える |
| 反映 | `cd ~/server/apps && docker compose build kvstore && docker compose up -d && cd ~` |

## 11-3. KVストアの復元（進捗がおかしくなったとき）

キーは例として `jsilver17_v1` を使います。

1. 履歴を見て、戻したいリビジョンを `savedAt` の日時で選ぶ：`curl -s "http://100.x.y.z:8081/api/kv/jsilver17_v1/history"; echo`
2. 中身を確かめる：`curl -s "http://100.x.y.z:8081/api/kv/jsilver17_v1/history/12"; echo`（12 は選んだ番号）
3. 戻す：`curl -s -X POST "http://100.x.y.z:8081/api/kv/jsilver17_v1/restore/12"; echo`
4. 開いている全端末でページを再読み込みする

キーに `:` を含む場合は URL で `%3A` にします（例 `jsq%3Astate%3Av1`）。
