## 17-3. Tailscale：なぜポートを開けずにつながるのか

Tailscale は、自分の端末同士だけをつなぐ VPN（暗号化された専用の通路）です。

| 言葉 | 意味 |
| --- | --- |
| tailnet | 自分専用のネットワーク。参加した端末に `100.x.x.x` の住所が1つずつ配られる |
| WireGuard | 通信を暗号化する仕組み。端末同士が直接暗号化するので、途中の誰にも中身は読めない。秘密鍵は各端末の中から出ない |
| コーディネーションサーバー | Tailscale 社のサーバー。「誰が参加しているか」と公開鍵の配布だけを担当する。通信の中身は通らない |
| MagicDNS | 端末を `your-mac.your-tailnet.ts.net` のような名前で呼べる仕組み |
| ACL | 「誰が、どの端末の、どのポートに届いてよいか」のルール |
| タグ | 端末に付ける名札（`tag:server`）。ACL で宛先として使う |
| 端末の承認 | 新しい端末は、管理画面で自分が承認するまで参加できない |
| Serve | tailnet の中だけに HTTPS で公開する機能 |
| Funnel | インターネット全体に公開する機能（この倉庫では使わない） |

ふつう、外から家の機械につなぐにはルーターに「穴」（ポート開放）を開けます。穴は世界中から見えるので攻撃されます。Tailscale では、Mac mini と iPhone の両方が**内側から外向きに**接続を張り、その2本を突き合わせてつなぎます。家のルーターは「内から外」の通信しか通していないので、穴は要りません。直接つなげない回線のときは Tailscale の中継サーバーを経由しますが、暗号化されたままなので中身は読まれません。

その代わり、Tailscale のアカウント（＝ログインに使っている GitHub）を乗っ取られると、攻撃者の端末を仲間として追加されてしまいます。だから GitHub の2段階認証と、端末の承認が最重要です。
