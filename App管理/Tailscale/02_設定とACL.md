# Tailscale の設定と ACL

外から届く経路は Tailscale だけです。ACL の控えは `acl.hujson` にあります（管理画面が正）。

外から届く経路は Tailscale だけで、その中でも「自分（owner）の端末 → サーバーの決めたポート」だけを許可しています。サーバーから手元の端末への通信は許可していないので、万一サーバーが乗っ取られても iPhone へは広がりません。

## 4-1. Tailscale の構成

| 項目 | 設定 | 理由 |
| --- | --- | --- |
| インストール版 | 公式サイト（スタンドアロン）版。`brew install --cask tailscale-app` | App Store 版はサンドボックス制約で CLI や `serve` が使えない |
| ログイン時に起動 | オン | オフだと再起動後に外から一切つながらない |
| タグ | `tag:server`（`--advertise-tags=tag:server --accept-routes`） | ACL で「サーバー宛てだけ許可」と書くため |
| MagicDNS | 有効 | `your-mac.your-tailnet.ts.net` で引ける |
| 端末の承認（Device approval） | オン（管理画面の表示は「新しいデバイスを手動で承認してください」） | 新しい端末は管理画面で承認するまで参加できない |
| キーの有効期限（Key expiry） | 180日（有効のまま。無期限にしない） | 半年ごとに GitHub での再認証が必要。切れると外出先からつながらなくなるので、家で再ログインする |
| 新しいデバイスの自動更新 | オン（10月2日に管理画面で確認） | 脆弱性の修正が自動で入る |
| Tailscale SSH | 使わない | macOS のアプリ版はサーバー側 SSH に非対応。OpenSSH で運用 |
| Tailscale Serve | 使っていない（辞書の単体版で一時使用し、停止済み） | HTTPS が必要なアプリが出たときの候補（13章 coupon-checker） |
| Tailscale Funnel | **使わない** | インターネット公開になるため設計原則に反する |
| Tailnet Lock | 使っていない。10月2日の管理画面では「使用不可」と表示 | そのときの説明は「デバイス承認とどちらか一方で、個人利用はデバイス承認で足りる」。10月9日には「いちばん強い対策だが、慣れてから」とも案内した。今の画面で選べるかは**要確認** |
| Mac・iPhone の Tailscale アプリの更新 | **要確認**（10月9日に自動アップデートを推奨） | アプリ自体の脆弱性は定期的に出る |

## 4-2. ACL（ポリシーファイル）全文

管理画面 → アクセス制御 → JSONエディタにある現在の内容です。新しい書き方の `grants` 形式を使っています（古い `acls` と混ぜると保存エラー）。

```json
{
	"tagOwners": {
		"tag:server": ["autogroup:admin"],
	},

	"grants": [
		{
			"src": ["autogroup:owner"],
			"dst": ["tag:server"],
			"ip": [
				"tcp:22",
				"tcp:443",
				"tcp:2283",
				"tcp:3000",
				"tcp:8081",
				"tcp:8082",
				"tcp:8083",
				"tcp:8084",
				"tcp:8090",
			],
		},
	],

	"ssh": [
		{
			"action": "check",
			"src":    ["autogroup:owner"],
			"dst":    ["autogroup:self"],
			"users":  ["autogroup:nonroot"],
		},
	],
}
```

| 部分 | 意味 |
| --- | --- |
| `src: autogroup:owner` | tailnet の作成者（自分）の端末だけ。`autogroup:admin` は別のロールで、書くと自分が締め出される恐れがある |
| `dst: tag:server` | 名札 `tag:server` の付いた端末（Mac mini）だけ |
| `ip` | 届いてよいポート。予約分（2283・8082〜8090 など）も含む |
| `ssh` ブロック | macOS では効かないが害はないので残してある |
| 書いていないこと | Mac mini から他の端末への通信。書かないものはすべて拒否される |

**変更の経緯**：初期値は全開放（`src:*` `dst:*` `ip:*`）→ `autogroup:member` で絞る → 将来家族を招待しても自動で全サービスに届かないよう `autogroup:owner` に変更。繋がらなくなったら、管理画面は ACL の影響を受けないので、画面から元に戻すか「ログ → 設定ログ」から復元できます。

## 4-3. ポート割当表

すべて `100.x.y.z` にバインドします。「予約」は ACL で許可済みだが、まだ何も待ち受けていない番号です。

| ポート | 用途 | 状態 |
| --- | --- | --- |
| 22 | SSH（OpenSSH、鍵認証のみ） | 稼働（macOS の仕様で全インターフェース待ち受け） |
| 443 | HTTPS（Tailscale Serve 等） | 予約 |
| 445 | SMB | 未許可。導入時に ACL へ追加し、共有設定もそのときにオン |
| 2283 | Immich | 予約 |
| 3000 | Homepage（ポータル） | 稼働 |
| 8081 | nginx（apps-static）。各アプリはこの配下のパス | 稼働 |
| 8082 | フラッシュカード（当初案） | 予約 |
| 8083 | 重要メール抽出の閲覧画面（当初案） | 予約 |
| 8084 | 疑通確認用（CP3 で python の一時サーバーに使用） | 予約 |
| 8090 | バス予約アプリ（Tomcat） | 予約 |
| 8443 | coupon-checker の HTTPS（Tailscale Serve 案） | 未導入。ACL にも未記載 |

> 当初は「アプリごとにポートを分ける」設計でしたが、KVストア以降は「8081 の nginx 配下にパスで分ける」方式に統一しました。ACL を触らずにアプリを足せ、公開ポートが増えないためです。予約ポートは使わないと決まったら ACL から外すと、より堅くなります。

## 4-4. Mac mini が待ち受けているポート（基準状態）

Docker のサービスを入れる前に記録した一覧です（`~/server/logs/baseline_ports.txt`、`*:` で始まるもののみ）。

| ポート | プロセス | 評価 |
| --- | --- | --- |
| `*:22` | launchd（SSH） | 必要。鍵認証のみ |
| `*:88` | kdc（Kerberos） | macOS 標準。放置 |
| `*:51794` `*:59305` `*:59306` | rapportd（Handoff） | Handoff を使うため残した |
| `*:59869` | logioptio（Logicool Options） | 周辺機器ソフト |
| `*:59657` `*:63413` | io.tailscale | 必要 |

閉じたもの：`*:445`（SMB）、`*:5000` `*:7000`（AirPlay レシーバー）。

Docker 側の正しい状態は「`com.docker.backend` が `100.x.y.z:3000` と `100.x.y.z:8081` だけを待ち受ける」です。**`*:8081` のように `*` で出たら設定ミス**（LAN 全体に公開されている）。macOS のファイアウォールは Docker のポート公開を止められないので、このバインド指定が実質的な防御です。
