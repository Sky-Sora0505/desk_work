# バックアップと復元

何をどう守るかと、外付けドライブ購入後の計画です。KVストアの復元手順は `App/kvstore/README.md` にあります。

今はデータがすべて内蔵 SSD にあり、定期的な外部バックアップはまだ組んでいません。外付けドライブ2台（稼働用 Drive A・バックアップ用 Drive B）を買ったら、下の計画どおりに組みます。GitHub への移行で「コードと設定」は先に守れるようになります。

## 11-1. 何をどう守るか

| 対象 | 場所 | 現在の守り | 引っ越し後 |
| --- | --- | --- | --- |
| compose・nginx 設定・スクリプト・自作アプリのコード | `~/server/apps` `homepage` `scripts` | `.bak-<日付>` の控えのみ | **GitHub（非公開）で履歴管理** |
| KVストアのデータ | `~/server/data/kvstore/` | 履歴（1キー30件）＋ API で作る `backup/`（直近10個、同じディスク上） | Drive B への週次バックアップに含める |
| 辞書のデータ | `~/server/data/dictionary/` | なし | 同上 |
| 秘密情報（`.env`、鍵） | 内蔵 SSD | FileVault | Time Machine に含める。GitHub には上げない |
| macOS 本体 | 内蔵 SSD | なし | Time Machine（専用ドライブ） |
| 写真・動画 | — | — | Drive A に Immich、Drive B へ週次 |

Time Machine が今有効かどうかは **要確認** です（システム設定 → 一般 → Time Machine）。

## 11-2. 今すぐできる手動バックアップ

| 対象 | コマンド |
| --- | --- |
| KVストア（止めずに取れる） | `curl -s -X POST http://100.x.y.z:8081/api/admin/backup; echo` → `ls -lh ~/server/data/kvstore/backup/` |
| 全データ（止めて取る） | `~/server/scripts/down.sh` → `cp -R ~/server/data ~/Desktop/server-data-$(date +%Y%m%d)` → `~/server/scripts/up.sh` |

**動いているまま `kvstore.db` や `dictionary.db` を直接コピーしない**でください。書き込み途中の壊れたコピーになることがあります。コピーするなら API で作ったファイルを使うか、止めてからにします。

## 11-4. 外付けドライブ購入後の計画

| 項目 | 内容 |
| --- | --- |
| Drive A（稼働用） | SSD。名前 `ServerData`、APFS、GUID パーティションマップ。`~/server/data` をここ（`/Volumes/ServerData/`）へ移す |
| Drive B（バックアップ用） | HDD でも可。普段は**取り外しておく**（ランサムウェア対策のオフライン保管） |
| 容量 | DJI 動画の撮影頻度次第で 2TB〜4TB |
| 方式 | サービスを止めて rsync で Drive A → Drive B（週に1回） |
| 目標 | RPO（どこまで戻せるか）最大1週間前、RTO（復旧時間）1日以内 |
| 穴埋め | スマホ側の元写真を Immich への取り込み後も一定期間残し、週次の雙間を埋める |

移すときは、compose の bind mount のパス（`/Users/youruser/server/data/…`）をすべて書き換えます。外付けドライブがマウントされる前に Docker が起動すると空のフォルダを見てしまうので、`up.sh` に「`/Volumes/ServerData` があるか」の確認を足します。
